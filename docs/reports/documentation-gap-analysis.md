## Clasificación de riesgo

`BLOCKER` impide declarar listo para producción · `CRITICAL` riesgo alto de integración,
seguridad u operación · `HIGH` ausencia relevante de claridad/trazabilidad · `MEDIUM` mejora
necesaria no bloqueante · `LOW` optimización editorial/visual.

## Nota sobre GAP-016

Es la única brecha de esta matriz que **no se cierra únicamente con documentación**: verificar que
`RLS_ENFORCE=true` y que el rol de aplicación (`DB_APP_USER`) no tiene `BYPASSRLS` requiere
inspeccionar la configuración real de cada entorno desplegado (staging, producción), algo que este
ejercicio de documentación estático no puede confirmar por sí solo. Se documenta el procedimiento
de verificación (Fase 13) pero **el cierre real de este BLOCKER depende de una acción operativa
fuera del repositorio**, y así debe quedar declarado en el informe final (Fase 18): no se puede
afirmar `APTO PARA PRODUCCIÓN` sin esa verificación, aunque toda la documentación esté completa.
